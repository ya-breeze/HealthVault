## 2. `off` package (mirrors `backend/pkg/usda`)

- [x] 2.1 Create `backend/pkg/off/off.go`: `Food` struct (`Code string`, `ProductName string`, `Brands string`, `Profile database.NutrientProfile`), `Index` type, `Open`/`Close`
- [x] 2.2 Implement `Index.Search(name, brand string, limit int) ([]Food, error)` — **`brand` is required (empty brand SHALL return no results, not "match anything"), and is a column-scoped predicate against `brands`, not a token OR'd in with the name terms.** Build the FTS5 MATCH query as an AND of two groups: brand terms required, AND name terms (`product_name:term1 OR product_name:term2 ...`) used for ranking within the brand-matched set. Within the brand group itself, **every token of the extracted brand is required together** (`brands:term1 AND brands:term2 ...` for a multi-word brand like "Dr. Oetker") — do **not** OR the brand's own tokens together (`brands:dr OR brands:oetker` would let an unrelated product like "Dr Pepper" match on "dr" alone). Do **not** flatten brand and name into one OR-joined query the way `usda.QueryFor` does for name/prep/state; that pattern is correct for USDA's ranking-only use and wrong here, where the brand match is the entire safety property (see design.md)
- [x] 2.3 Implement `Index.ByCode(code string) (*Food, error)` for binding a chosen candidate — only ever called on an open `Index`; the caller checks for a nil/absent index separately (mirroring `h.usda == nil` in `resolveReferenceProfile`) rather than expecting `ByCode` to report "no database" itself
- [x] 2.4 Implement `Index.Count()`
- [x] 2.5 Define schema: `off_foods` table (`code TEXT PRIMARY KEY`, `product_name`, `brands`, `calories`, `protein`, `carbs`, `fat`, `sugar`, `sodium`, `fiber`) + FTS5 virtual table over `product_name`, `brands`
- [x] 2.6 Implement `Builder`/`Add`/`Promote`/`Discard` with the same build-to-temp-then-atomic-rename pattern and a `MinExpectedRows` guard as `usda.Builder`
- [x] 2.7 Create `backend/pkg/off/query.go` with `sanitizeFTSQuery` (adapted from `usda/query.go`, reused for tokenizing both the brand group and the name group) and the brand-required/name-ranking query builder described in 2.2 — brand tokens joined with AND, name tokens joined with OR, the two groups joined with AND

## 3. Open Food Facts import

- [x] 3.1 Create `backend/pkg/off/import.go`: fetch the OFF export (URL or local path, mirroring `usda.Fetch`'s flexibility) and stream-parse it as gzip-compressed JSONL (avoids loading the full export into memory; handle gzip decoding explicitly)
- [x] 3.2 Filter during import: keep only products whose `countries_tags` includes Czech Republic and/or Slovakia
- [x] 3.3 Map nutriments explicitly per design.md's "Explicit per-field mapping" decision: calories from `nutriments.energy-kcal_100g` only (never `energy_100g`/`energy-kj_100g`); sodium from `nutriments.sodium_100g`, falling back to `nutriments.salt_100g / 2.5` when only salt is present, defaulting to 0 when neither is present; protein/carbs/fat/sugar/fiber from their direct `_100g` fields, defaulting sugar/fiber to 0 when absent. A product missing calories or missing protein/carbs/fat is excluded as incomplete — sodium/sugar/fiber absence does NOT exclude a product, matching the completeness bar already stated in the off-nutrition-database spec (calories/protein/carbs/fat only)
- [x] 3.4 Distinguish two different error classes and handle them oppositely: a single JSON object that fails to decode (e.g. one malformed line in the JSONL stream) SHALL be skipped and counted, continuing the import; an error from the underlying reader/gzip decoder itself (corrupt or truncated gzip, unexpected EOF mid-stream, read failure) SHALL abort the entire import immediately and discard the build via `Builder.Discard`, NOT be treated as "one more skippable row." A truncated gzip stream can otherwise yield thousands of valid rows before erroring at EOF — enough to clear `MinExpectedRows` — and get silently promoted as a complete import if its terminal read error is absorbed into the same skip-and-continue path as a malformed row
- [x] 3.5 Call `Builder.Add` for each kept, mapped product
- [x] 3.6 Create `backend/cmd/commands/cmdimportoff.go`: cobra command `import-off`, following `cmdimportusda.go`'s structure (fetch → build → promote → report count, including skipped/malformed row count)
- [x] 3.7 Register the new command alongside `import-usda` in the CLI root
- [x] 3.8 Add `OFF_DB_PATH` to `backend/pkg/config/config.go` (default e.g. `./data/off.db`), following the existing `USDA_DB_PATH` pattern exactly
