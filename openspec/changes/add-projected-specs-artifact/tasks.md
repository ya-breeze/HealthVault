## 1. Generator script

- [x] 1.1 Create `scripts/generate-projected-specs.sh`: accept an optional base-ref argument (default `origin/main`), compute touched change ids via `git diff --name-only "$BASE"...HEAD -- ':(glob)openspec/changes/*/specs/**'` — the `:(glob)` magic is required, not cosmetic: git's default (non-glob) pathspec lets `*` match across `/`, so the unmagic'd form falsely matches an archived-and-committed delta at `openspec/changes/archive/<date>-<id>/specs/**`, yielding the bogus change id `archive`
- [x] 1.2 Zero-touched-ids path: `rm -rf openspec/specs.projected` and exit 0
- [x] 1.3 Before creating any worktree: for each touched change id, parse its delta files under `openspec/changes/<id>/specs/**/spec.md` for `### Requirement: <name>` headers (any of ADDED/MODIFIED/REMOVED), for `## RENAMED Requirements` entries (`- FROM: `### Requirement: <old>`` / `- TO: `### Requirement: <new>`` pairs, treating both `<old>` and `<new>` as touched names), *and* for OpenSpec's bullet form of `REMOVED Requirements` (`- `### Requirement: <name>``, matching the `openspec` CLI's own `parseRemovedNames` regex — not just the header form); build `(capability, requirement name)` pairs per change id from all of these. If the same pair appears under more than one touched change id, print the conflicting change ids and requirement name and exit non-zero without creating a worktree or touching `openspec/specs.projected/`
- [x] 1.4 Non-empty, non-conflicting path: create a detached worktree (`git worktree add --detach <tmp> HEAD`) with a `trap` that removes it on any exit (success, failure, or interrupt)
- [x] 1.5 Inside the worktree, run `openspec archive <id> --yes` for each touched id in sorted order; on any failure, print the error and exit non-zero without touching `openspec/specs.projected/` in the primary tree
- [x] 1.6 From the touched change ids' delta paths, derive the touched-capability set (the path segment after `specs/` in each changed delta file)
- [x] 1.7 On success, rebuild `openspec/specs.projected/` from scratch (`rm -rf openspec/specs.projected && mkdir`), writing output only for touched capabilities — never the full `openspec/specs/` tree
- [x] 1.8 For each touched capability, write `openspec/specs.projected/<capability>/spec.md` (full post-archive text from the worktree) and `openspec/specs.projected/<capability>/spec.diff` via `diff -u --label "openspec/specs/<capability>/spec.md" --label "openspec/specs/<capability>/spec.md" <before> <after>` (before = `git show HEAD:openspec/specs/<capability>/spec.md` materialized to a temp file, or `/dev/null` if the path doesn't exist at `HEAD`; after = post-archive text) — fixed labels, not the worktree's real temp path, so output is deterministic across runs; the "before" side reads committed `HEAD`, not the primary working tree's file, so an uncommitted local edit can't change the output. Clean up the "before" temp file with a proper `if`, not a bare `[[ ... ]] && rm -f ...` — under `set -e`, that shortcut aborts the whole script whenever `before_tmp` is empty (the brand-new-capability case)
- [x] 1.9 Prepend the generated-file header comment to every `.md` and `.diff` file written, naming `make projected-specs` as the regeneration command and pointing to `openspec/specs.projected.README.md` for the full explanation
- [x] 1.10 Make the script executable (`chmod +x`) and verify `shellcheck` (if available) reports no issues
