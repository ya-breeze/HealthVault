## 1. Generator script

- [ ] 1.1 Create `scripts/generate-projected-specs.sh`: accept an optional base-ref argument (default `origin/main`), compute touched change ids via `git diff --name-only "$BASE"...HEAD -- ':(glob)openspec/changes/*/specs/**'` — the `:(glob)` magic is required, not cosmetic: git's default (non-glob) pathspec lets `*` match across `/`, so the unmagic'd form falsely matches an archived-and-committed delta at `openspec/changes/archive/<date>-<id>/specs/**`, yielding the bogus change id `archive`
- [ ] 1.2 Zero-touched-ids path: `rm -rf openspec/specs.projected` and exit 0
- [ ] 1.3 Before creating any worktree: for each touched change id, parse its delta files under `openspec/changes/<id>/specs/**/spec.md` for `### Requirement: <name>` headers (any of ADDED/MODIFIED/REMOVED) *and* for `## RENAMED Requirements` entries (`- FROM: `### Requirement: <old>`` / `- TO: `### Requirement: <new>`` pairs, treating both `<old>` and `<new>` as touched names); build `(capability, requirement name)` pairs per change id from all of these. If the same pair appears under more than one touched change id, print the conflicting change ids and requirement name and exit non-zero without creating a worktree or touching `openspec/specs.projected/`
- [ ] 1.4 Non-empty, non-conflicting path: create a detached worktree (`git worktree add --detach <tmp> HEAD`) with a `trap` that removes it on any exit (success, failure, or interrupt)
- [ ] 1.5 Inside the worktree, run `openspec archive <id> --yes` for each touched id in sorted order; on any failure, print the error and exit non-zero without touching `openspec/specs.projected/` in the primary tree
- [ ] 1.6 From the touched change ids' delta paths, derive the touched-capability set (the path segment after `specs/` in each changed delta file)
- [ ] 1.7 On success, rebuild `openspec/specs.projected/` from scratch (`rm -rf openspec/specs.projected && mkdir`), writing output only for touched capabilities — never the full `openspec/specs/` tree
- [ ] 1.8 For each touched capability, write `openspec/specs.projected/<capability>/spec.md` (full post-archive text from the worktree) and `openspec/specs.projected/<capability>/spec.diff` via `diff -u --label "openspec/specs/<capability>/spec.md" --label "openspec/specs/<capability>/spec.md" <before> <after>` (before = current `openspec/specs/<capability>/spec.md`, or `/dev/null` if new; after = post-archive text) — fixed labels, not the worktree's real temp path, so output is deterministic across runs
- [ ] 1.9 Prepend the generated-file header comment to every `.md` and `.diff` file written, naming `make projected-specs` as the regeneration command and pointing to `openspec/specs.projected.README.md` for the full explanation
- [ ] 1.10 Make the script executable (`chmod +x`) and verify `shellcheck` (if available) reports no issues

## 2. Task runner and CI integration

- [ ] 2.1 Add a `projected-specs:` target to the root `Makefile` that runs `scripts/generate-projected-specs.sh`
- [ ] 2.2 Add `.github/workflows/openspec-projected-specs.yml`: trigger on `pull_request` with a `paths` filter on `openspec/**`; checkout with `fetch-depth: 0`; install `@fission-ai/openspec@1.6.0` via npm; run the script against `origin/${{ github.base_ref }}`; run `git add -A -- openspec && git diff --cached --exit-code -- openspec/specs.projected` (staged comparison from the always-present `openspec` parent path, not `openspec/specs.projected` directly — staging that path directly errors when it has never existed on the checkout, which is the correct empty-final-state case — and not a plain working-tree diff, so an entirely untracked/missing projection is also caught) and fail with a message naming `make projected-specs` as the fix
- [ ] 2.3 Add `.gitattributes` entry: `openspec/specs.projected/** linguist-generated=true`

## 3. Documentation

- [ ] 3.1 Add `openspec/specs.projected.README.md` — **not** inside `openspec/specs.projected/` itself, since tasks 1.2 and 1.7 `rm -rf` that entire directory on every run (including down to empty on the zero-touched-changes path), which would silently delete a hand-authored file placed inside it and make the CI drift check flag its own deletion as stale output — describing: what the directory is, that it is generated and never hand-edited, how to regenerate (`make projected-specs`), the empty-on-main lifecycle invariant, that PR review should read the projected file for final wording and the delta under `openspec/changes/<id>/specs/` for intent, and the exact two-commit finishing sequence — (1) `openspec archive <id> --yes` then commit that move on its own, (2) only then `make projected-specs` then commit the resulting removal — spelled out as two distinct commit steps, not paraphrased as one combined "archive and regenerate" step, since running both before committing the first does not reach the empty state (discovery and the worktree are both `HEAD`-based). Reference this file's path from the generated-file header comment (task 1.9) so a reader landing on a generated file can find it.
